# Syphere Parcelbox for Home Assistant

**Release: v0.2.1 — Credential Login Fix**

Unofficial Home Assistant custom integration for the Syphere Parcelbox cloud service.

> [!IMPORTANT]
> This project is community-developed and is **not affiliated with, endorsed by, or supported by Synomics/Syphere**. It uses an undocumented API observed from legitimate use of the official app. The API can change without notice.

## What v0.2.1 fixes

The initial Syphere login now reproduces the wire format observed from the official iOS app:

- `POST /api/oauth/token`
- `Content-Type: application/x-www-form-urlencoded`
- compact JSON sent as the **raw request body**
- fields: `username`, `password`, `grant_type=password`, `client_id`

The official app's OAuth Client ID is used internally, so normal Home Assistant setup only asks for **email and password** (plus the API base URL if you want to override it). OAuth client IDs are application identifiers, not client secrets.

The password is used only for the initial token exchange and **is never persisted** in the Home Assistant config entry. After login, Home Assistant stores the access token, refresh token and resolved client ID and automatically rotates tokens when required.

## Features

- Direct Syphere email/password setup
- Automatic OAuth token refresh
- Cloud status polling from `GET /api/user/homepage`
- Delivery-present and fixed-lockbox binary sensors
- Deposition state and active size sensors
- Deposition-enabled and Bluetooth-reachability binary sensors
- Dynamic compartment-size discovery from `GET /api/deposition/size`
  - no hard-coded assumption that only S/M/L exist
  - new size labels are discovered automatically
- Reserve the selected available compartment size
- Cancel the current deposition
- Open the delivery compartment
- Privacy-minimized diagnostics

## Privacy and security

The Syphere API may return personal names, Bluetooth identifiers, delivery PINs and personal PINs. This integration deliberately discards those fields and does not expose them as entities or diagnostics.

The account email, OAuth access token, refresh token and Client ID are redacted from Home Assistant diagnostics. The Syphere password is never saved by the integration.

**Never paste tokens, PINs, packet captures or full proxy exports into public GitHub issues.**

See [Security and privacy](docs/SECURITY_AND_PRIVACY.md).

## Installation

### HACS custom repository

Publish this folder as a GitHub repository, add it to HACS as a custom repository of type **Integration**, install **Syphere Parcelbox**, then restart Home Assistant.

### Manual

Copy:

```text
custom_components/syphere_parcelbox/
```

into:

```text
/config/custom_components/syphere_parcelbox/
```

and restart Home Assistant.

## Configuration

Go to:

**Settings → Devices & services → Add integration → Syphere Parcelbox**

Enter:

- **Email** — your Syphere account email
- **Password** — used only for the login exchange; not stored
- **API base URL** — normally leave the default `https://pbb.syphere.net:9997`

After successful login the integration validates the session against `/api/user/homepage`, derives a one-way device fingerprint for duplicate detection, and stores only the token/session data required for future API access.

## Entities

Typical entities include:

- `binary_sensor.*_delivery_present`
- `binary_sensor.*_fixed_lockbox`
- `binary_sensor.*_deposition_enabled`
- `binary_sensor.*_bluetooth_reachable`
- `sensor.*_deposition_state`
- `sensor.*_deposition_size`
- `sensor.*_available_compartment_sizes`
- one availability binary sensor for every size returned by Syphere
- `select.*_deposition_size`
- `button.*_reserve_deposition`
- `button.*_cancel_deposition`
- `button.*_open_delivery_compartment`

Entity IDs are generated by Home Assistant and can vary with language/naming.

## Reservation flow

The integration does **not** store backend lockbox IDs. On every reservation it:

1. fetches the current size list,
2. finds the selected size that is currently available,
3. uses the current backend ID returned by Syphere,
4. creates the reservation,
5. refreshes Home Assistant state.

This avoids stale or installation-specific compartment IDs.
